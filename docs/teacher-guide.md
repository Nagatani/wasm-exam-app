# 講師向けガイド

試験・問題・テストケース・解答例の作り方と、成績の確認方法です。

## 前提

- 講師アカウントが必要です。最初の1人はDBで昇格させます（[README](../README.md#最初の講師アカウントの作成)参照）。2人目以降は講師ダッシュボードの「学籍番号を指定して教員に昇格」フォームで対応できます。
- ログイン後、講師は自動で `/teacher`（講師ダッシュボード）に遷移します。ダッシュボード上部に **DB / Java judge のサービス状態**が表示されます（30秒間隔で更新）。

## クラス（受講者名簿）

`/teacher` の「クラス管理」から、クラス（授業・クラス分け）を作成し受講者を登録できます。

- クラス名・学期（任意）で作成。
- クラスを開くと受講者一覧と2つの追加欄が出ます。
  - **受講者を追加**（既存アカウント）：学籍番号を1行ずつ、またはCSVを貼り付け（各行の先頭列を学籍番号として読む）。既にアカウントのある学生だけが登録され、見つからない学籍番号は結果に表示されます。
  - **生徒アカウントを一括作成**：1行に「学籍番号,氏名」で貼り付け（CSV可）。既存の学籍番号はスキップ。作成した各アカウントには**ランダムな初期パスワード**が発行され、作成後に**初期パスワード一覧が印刷用ウィンドウ**で開きます（学籍番号・氏名・初期パスワード）。このクラスにも自動で登録されます。
- 初期パスワードは、生徒が初回ログインで自分のパスワードに変更するまで受講者一覧に 🔑 で表示され、「初期パスワード一覧を印刷」で再印刷できます。**生徒が変更した時点で初期パスワードは無効・非表示になります。**
- 受講者は行の「削除」で外せます（アカウント自体は残ります）。
- **試験にクラスを指定**すると、その試験は**そのクラスの受講者だけ**に表示・受験可能になります（クラス未指定の試験は従来どおり全生徒に公開）。成績ダッシュボード／CSV も、クラス指定がある試験ではそのクラスの受講者だけを一覧します。
- クラスを削除しても試験は残ります（クラス指定が外れて全生徒公開に戻ります）。

## 全体の流れ

```
試験を作る（非公開）
  └─ 問題を追加する
       ├─ 解答言語を選ぶ
       ├─ 問題文を書く
       ├─ 初期テンプレートコードを用意する
       ├─ テストケースを追加する（サンプル / 非公開）
       └─ 解答例コードを登録する（任意・生徒には非公開）
試験を「公開中」にする  ← これで初めて生徒に見えます
受験後、成績を確認 / CSV 出力する
```

## 1. 試験を作る

`/teacher` の「＋ 新規試験作成」から、タイトル・説明（任意）・制限時間（分）・**受験可能回数**・**公開開始日時 / 受付終了日時**（任意）を入力して作成します。作成直後の公開ステータスは **非公開（DRAFT）** です。

受験可能回数は既定 **1回**、「無制限」にもできます（任意のN回も可）。複数回受験できる場合、**最後に提出した回の点数**がその試験の成績になります（最高点ではありません）。

## 2. 試験の設定と問題の追加

試験名をクリックすると試験詳細（`/teacher/exams/:examId`）に入ります。ここで:

- タイトル・説明・制限時間・**受験可能回数**の編集
- **クラス**（任意）の指定 — 指定するとそのクラスの受講者だけに公開されます
- **公開開始日時 / 受付終了日時**（任意）の設定
- **公開ステータス**（非公開 / 公開中）の切り替え
- 「＋ 問題を追加」で問題を作成（作成すると問題編集画面に移動します）
- 問題一覧の各行の「複製」で、その問題（問題文・言語・テンプレート・配点・比較設定・テストケース・解答例ごと）をこの試験の末尾に複製
- 問題の出題順は、各行の ⠿ をドラッグするか、行の ▲▼ ボタンで並び替えられます（テストケースの並び順も問題編集画面で同様に並び替えられます）
- 「成績を見る」で成績ダッシュボードへ

制限時間は、生徒がその回の受験を**開始した時刻**からのカウントダウンです（一覧に表示された時点ではなく、受験を開始した時点が起点）。複数回受験の場合、回ごとにカウントダウンは最初からになります。

**公開開始日時 / 受付終了日時**（任意・講師のローカル時刻で入力）:

- 公開開始日時より前は、公開中でも生徒は一覧に見えても受験を開始できません（「公開開始: 〜」と表示）。
- 受付終了日時を過ぎると、新しい受験を開始できません。受験中の回は、制限時間より前でも受付終了時刻で自動提出されます（＝各回の締切は「開始＋制限時間」と「受付終了日時」の早い方）。

## 3. 問題を編集する

問題編集画面（`/teacher/exams/:examId/tasks/:taskId`）の各項目:

### タイトル・表示順・配点

既定では、配点は全テストケースACのときだけ入ります（部分点はありません）。「部分点を認める」（出力の比較方法の隣）を有効にすると、通過したテストケース数（サンプル・非公開とも）に比例した点数を四捨五入で採点します。コンパイルエラーの場合はどちらの設定でも0点です。

### 解答言語

`C` / `Java` / `JavaScript` / `TypeScript` / `Python` から **1つ** を選びます。生徒側に言語の選択肢はなく、ここで指定した言語だけで解答します。エディタのシンタックスハイライトと実行方式もこの選択で決まります。

言語ごとの標準入出力の作法・制限は必ず **[languages.md](./languages.md)** を確認し、**問題文に入出力形式を明記してください**（例: 「1行目に整数nが与えられる。nを2倍にして1行で出力せよ」）。

### 問題文（Markdown）

Markdownで書けます。**編集 / 分割 / プレビュー**の3表示を切り替えられます（分割は左に入力・右にライブプレビュー）。セキュリティのため生のHTMLは無効です（`<script>` などは描画されません）。

「画像を挿入」ボタンから画像（PNG / JPEG / GIF / WebP、5MB以下）をアップロードでき、カーソル位置に自動で `![]()` が挿入されます（プレビュー表示中は文末に追加）。アップロードした画像は誰でもURLを知っていれば閲覧できます（学籍番号・成績などの個人情報とは異なり、問題文の図版として公開情報扱いのため）。

### 出力の比較方法

問題ごとに、テストケースの「期待される出力」と「実際の出力」の突き合わせ方を選べます（既定は「完全一致」）。

| モード | 内容 |
|---|---|
| 完全一致 | 前後の空白のみ除いて文字列比較（従来の挙動） |
| 行末の空白と末尾の空行を無視 | 各行の行末空白と、末尾の空行を無視 |
| 空行をすべて無視 | 上に加えて途中の空行もすべて無視 |
| 数値を許容誤差付きで比較 | 空白区切りトークンで比較し、数値は「許容誤差」以内なら一致（非数値は完全一致）。誤差の値も同じ画面で設定 |

### 初期テンプレートコード

生徒がその問題を開いたときにエディタへ最初から入っているコードです。選んだ言語のエディタで編集し、**問題フォーム下部の「保存」**（タイトル等と一緒）で保存されます。

### テストケース

「＋ テストケースを追加」で行を足し、各行に:

- **入力（stdin）**: プログラムの標準入力に流し込まれる文字列
- **期待される出力（stdout）**: 正解の標準出力（前後の空白を除いて完全一致で判定）
- **サンプルかどうか**（チェックボックス）

テストケースは**行ごとに独立した「保存」ボタン**で保存します（問題フォームの「保存」とは別）。

**一括追加**：「一括追加」ボタンを押すと、複数のテストケースをまとめて貼り付けて追加できます。書式は、ケースの区切りが `===` だけの行、入力と期待される出力の区切りが `---` だけの行、ケースの1行目を `@sample` にするとサンプル扱い。既存のテストケースの後ろに追加されます。

| 種別 | 生徒に見える情報 |
|---|---|
| サンプル | 入力・期待される出力の**両方** |
| 非公開（サンプルでない） | 入力**のみ**（期待される出力はブラウザに一切送られません） |

判定ルールの詳細は [languages.mdの「採点の共通ルール」](./languages.md#採点の共通ルール)を参照。

> テストケースごとの制限時間（100〜15000ms）・メモリ（16〜512MB）は、**JavaまたはC（再採点時）**の問題でのみテストケース行に入力欄が表示されます。既定値は2秒 / 256MBです。C / JS / TS / Pythonの**生徒側の実行**は言語ごとの固定値（採点環境からは制御不可）のため、これらの言語の問題では入力欄自体が表示されません。

**既存の提出を再採点（Java・C）**：テストケースや期待出力を直した後、Java・Cの問題では「既存の提出を再採点」ボタンで、保存済みの全提出を現在のテストケース・比較設定で採点し直せます（判定・得点が上書きされます）。JS / TS / Python はサーバー側で再実行できないため対象外です。

### 解答例コード（任意）

模範解答を登録できます。**生徒には一切公開されません**（生徒向けAPIは解答例テーブルに触れません）。独立した「保存」ボタンで保存します。

**「解答例でテストケースを検証」**：エディタの解答例コードを全テストケースに対して実行し、各ケースの「期待される出力」と「解答例の出力」を突き合わせて表示します（C/JS/TS/Python はブラウザ内で、Java は judge コンテナで実行。保存はされません）。

- すべて「一致」なら、期待される出力が解答例と整合していることを確認できます。
- 「不一致」「実行時エラー」の行では、解答例が正しいと確認できた場合に限り「**実際の出力を期待値にする**」で期待される出力をその場で上書きできます（`PATCH /api/test-cases/:id` が即時実行されます）。
- Java で judge が未起動のときは検証できません（[operations.md](./operations.md)）。

## 4. 公開する

試験詳細で公開ステータスを **公開中（PUBLISHED）** にすると、生徒のダッシュボードに表示され受験できるようになります。非公開の試験は生徒からは存在も分かりません。

公開前に、試験詳細の**「公開前チェック」**を確認してください。テストケース未登録・サンプルなし・配点0・比較モードと期待出力の不整合・Java judge 未設定・日時の矛盾などを ⚠（要修正）／△（注意）で表示します。エラーがあっても公開自体はできますが、生徒が正しく受験できない可能性があります。

## 生徒側の受験・提出の流れ（参考）

生徒には言語選択も、設問ごとの提出もありません。

1. ダッシュボードで「受験する」を押すと、その回の受験（attempt）が始まりカウントダウンが開始します。
2. 各設問では「下書き保存」で解答を一時保存します（**採点はされません**）。設問間は自由に行き来でき、下書きは受験中いつでも上書きできます。
3. すべて確認したら「試験を提出する」→「最終提出する」。ここで初めて全設問がまとめて採点され、その回の成績が確定します。**提出後の修正・再提出はできません。**
4. 制限時間が切れると、その時点の下書きが**自動的に最終提出**されます（生徒のブラウザが閉じていた場合はサーバー側で確定。ブラウザ言語（C/JS/TS/Python）の設問は再実行できないため 0 点として確定します）。
5. 受験可能回数が残っていれば、結果画面から「もう一度受験する」で次の回を白紙から始められます。成績は**最後に提出した回**のものになります。

## 5. 成績を確認する

試験詳細の「成績を見る」→ `/teacher/exams/:examId/results`。

- **全 `STUDENT` アカウント**が行として並びます（その試験に触れていない生徒も「未提出」で表示）。
- 各問題について、その生徒の**最後に提出した回**の判定（AC/WA/CE/TLE/MLE）・得点・提出日時。
- 合計点、**受験回数**（提出済みの回数）、受験開始から最終提出までの所要時間、打鍵数・貼り付け量など（打鍵/貼り付け/所要時間は生徒のブラウザからの自己申告値で、`code` と同じ信頼度です）。
- 最後の回で提出しなかった問題の状態は「未提出」で、`WA` とは区別されます。
- 行を展開して「**提出コードと結果を表示**」を押すと、その生徒の最終提出回の**提出ソースコード**と、テストケースごとの入力・期待される出力・実際の出力・判定が見られます（非公開テストケースも含む）。
- **延長**列に分数を入れると、その生徒だけ制限時間（と、受付終了日時があればその生徒の締切）が延長されます（配慮対応）。0で解除。受験開始前・受験中どちらでも設定でき、複数回受験でも各回に効きます。ただし受付終了日時を過ぎてからの新規受験開始はできません。

### CSV出力

同じ画面からCSVをダウンロードできます。

- 列: `学籍番号,氏名,試験名,<各問題のタイトル…>,合計点,受験回数,提出日時,所要時間（秒）,…`
- Excelが日本語CSVの文字コードを誤判定しないよう先頭にBOMが付きます。
- ファイル名は日本語（試験名）に対応しています。

### 差し戻し（受験そのものをなかったことにする）

成績画面から、特定の生徒の特定の試験について「その試験の提出・受験記録（全回分）をすべて削除」できます。次にその生徒が試験を開くと 1 回目の受験としてカウントダウンが最初から始まります。

これは「受験可能回数の範囲で生徒が自分でもう一度受ける」のとは別物で、**全記録の消去**です。提出は本来不可逆で、これが唯一その原則を破る操作です。誤操作に注意してください。

## 受験画面のプレビュー

生徒用のURL（`/student/exams/:examId/tasks/:taskId`）は講師でも開けるため、受験画面をそのまま確認できます。ただし講師が「受験する」で受験を開始し**「最終提出する」まで進めると、講師自身の受験・提出として記録されます**。確認は下書き保存・「実行」までに留めるか、後で差し戻しで消してください。

`/teacher/sandbox` は言語実行の単体確認用ハーネスです（本番の受験フローとは独立）。
