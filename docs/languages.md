# 対応言語ガイド

問題は **1問につき1言語**で、講師が問題編集画面で選びます。生徒側に言語の切り替えはありません。

このドキュメントは「その言語で解答を書くとき／その言語の問題を作るときに知っておくべきこと」をまとめたものです。問題文（Markdown）に入出力形式を明記するときの参考にしてください。

## 採点の共通ルール

- **判定はサーバー**が行います。生徒のブラウザは「各テストケースの標準出力」と「コンパイル成否」だけを報告し、合否そのものは申告できません（クライアントを改造しても、保存済みの期待出力と一致しない限りACにはなりません）。Javaは例外で、ソースをサーバーに送りサーバー側でコンパイル・実行します。
- **出力比較は前後の空白を除いて完全一致**（`期待される出力` と `プログラムの標準出力` の両方を `trim()` してから文字列比較）。
  - `42` と `42\n`（末尾改行）→ 一致
  - `1 2` と `1  2`（間の空白が違う）→ 不一致
  - 途中の改行は区別されます。
- 1テストケースの結果は次のいずれか:
  - **AC** … 出力が期待値と一致
  - **WA** … 出力が期待値と不一致
  - **RE** … 実行時エラー（例外・異常終了・タイムアウト）。全体の判定では **WA** に丸められます（`TLE`/`MLE` の独立表示はフェーズ6で対応予定）。
- 問題全体の判定:
  - **AC** … 全テストケースがAC（配点が入る）
  - **WA** … 1つでもACでないテストケースがある（0点）
  - **CE** … コンパイル／構文エラー（0点）
- サンプルではないテストケースの「期待される出力」は生徒のブラウザに一切送られません。生徒は入力値だけ見えます。
- 設問画面の「実行」は採点結果を表示するだけ（保存なし）、「下書き保存」は解答を一時保存するだけ（採点なし）です。採点は試験全体の「最終提出」時に、保存済みの各下書きをまとめて行います。最終提出後の修正・再提出はできません（受験可能回数が残っていれば、白紙の新しい回として受け直せます）。制限時間切れ時はその時点の下書きが自動的に最終提出されます。

## 送信できるソースコードの上限

全言語共通で **200,000バイト**（UTF-8）です。

## C

| 項目 | 内容 |
|---|---|
| 実行場所 | 生徒のブラウザ（WASI / `@wasmer/sdk`、`clang` をWebAssemblyで実行） |
| コンパイル単位 | `main.c` |
| 標準入出力 | 通常どおり `stdin` / `stdout`（`scanf`, `printf` など） |
| 使えるもの | C標準ライブラリ。ファイルI/O・ネットワーク・時刻などの環境依存機能は使えません |
| 実行時間の上限 | **なし**（フェーズ6で対応予定）。無限ループを書くとそのタブが固まります |
| 初回コスト | clangツールチェイン ~106MBを初回のみダウンロード。低速回線だと最初のコンパイルに数分かかることがあります（以降はブラウザキャッシュ） |

## JavaScript

| 項目 | 内容 |
|---|---|
| 実行場所 | 生徒のブラウザ（使い捨てのWeb Worker） |
| 実行時間の上限 | **10秒**（超えるとWorkerを強制終了してRE扱い） |
| コンパイルエラー | 構文エラーのみ（実行前にパースして検出） |

`process` や `require` はありません。代わりに以下のグローバルが注入されます。

| 名前 | 用途 |
|---|---|
| `readline()` | 標準入力を1行返す（改行は含まない）。行がなくなったら `''` |
| `readLine()` | `readline()` の別名 |
| `read()` | 残りの標準入力を丸ごと文字列で返す |
| `print(...args)` | 引数をスペース区切りで出力し、末尾に改行。オブジェクトはJSONで出力 |
| `console.log` / `.error` / `.warn` / `.info` / `.debug` | すべて標準出力へ（`print` と同じ挙動） |
| `write(s)` | 改行なしで出力 |

- トップレベル `return` は使えます（コードは関数本体として実行されます）。
- **トップレベル `await` は使えません**。
- 各テストケースは毎回まっさらなWorkerで実行されるため、グローバル変数はテストケース間で引き継がれません。

**例（`n` を2倍にして出力）**

```js
const n = Number(readline());
console.log(n * 2);
```

## TypeScript

JavaScriptと同じランナーで動きます。実行前に **`sucrase` で型注釈を除去するだけ**で、型チェックは行いません。

- **型エラーは採点に影響しません**（`sucrase` は型を消すだけ）。
- **構文エラーはコンパイルエラー（CE）** になります。
- 入出力ヘルパー・制限・注意点はJavaScriptと同じ（`readline()` / `print()` など、10秒上限、トップレベル `await` 不可）。
- 型定義（`lib.d.ts`）は読み込まれないため、`document` やNodeの型など「型としては存在するが実行時にない」ものに依存しないでください。

**例**

```ts
const n: number = Number(readline());
const doubled: number = n * 2;
console.log(doubled);
```

## Python

| 項目 | 内容 |
|---|---|
| 実行場所 | 生徒のブラウザ（Pyodide = CPythonをWebAssembly化、Web Worker内） |
| 実行時間の上限 | **15秒**（超えるとWorkerを強制終了してRE扱い） |
| 初回コスト | Pyodideランタイム ~10MBをCDNから初回のみ取得 |
| コンパイルエラー | 構文エラーのみ（実行前に `compile()` で検出） |

- 標準入力・出力は通常どおり `input()` / `print()` / `sys.stdin` / `sys.stdout`。
- 使えるのは **Python標準ライブラリのみ**。`pip` / `micropip` は無効で、`numpy` などのサードパーティパッケージは読み込まれません。ネットワークアクセスもできません。
- `sys.exit()` / `exit()` での終了は正常終了として扱われます。
- 例外を送出すると、トレースバックが標準エラーに出てRE扱いになります。
- モジュールのimportはテストケース間で引き継がれますが、ユーザーコードは毎回まっさらなグローバル名前空間で実行されます。

**例**

```python
n = int(input())
print(n * 2)
```

## Java

| 項目 | 内容 |
|---|---|
| 実行場所 | **サーバー**（`judge` Dockerコンテナ内。ホストでは一切実行しません） |
| JDK | **24**、`--enable-preview` 付き（JEP 495「Simple Source Files and Instance Main Methods」が使えます） |
| コンパイル単位 | `Main.java`、エントリクラスは **`Main`** |
| 標準入出力 | 通常どおり `System.in` / `System.out`（`Scanner` など） |
| 実行時間の上限 | **テストケースごとの制限時間**（既定2秒、上限15秒）。超過でプロセスを強制終了してRE扱い |
| メモリの上限 | テストケースごとの設定（既定256MB、上限512MB）を `-Xmx` に適用 |
| 使えるもの | JDK標準ライブラリ。ネットワークは遮断。標準出力・標準エラーは64KBを超えると以降を切り捨て |

- クラス宣言を書く場合、公開クラス名は **`Main`** にしてください（`public class Solution` などはファイル名不一致でコンパイルエラーになります）。
- JEP 495のコンパクトソース（クラス宣言なしのインスタンス `main`）も使えます。生成されるクラス名は `Main` になります。
- `judge` コンテナが起動していない／`server/.env` の `JUDGE_URL` が空の場合、Javaの問題は生徒側で「準備中」表示になり実行・提出できません。運用は [`operations.md`](./operations.md)を参照。

**例（クラスあり）**

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        System.out.println(n * 2);
    }
}
```

**例（JEP 495コンパクトソース）**

```java
void main() {
    var sc = new java.util.Scanner(System.in);
    System.out.println(sc.nextInt() * 2);
}
```

## 言語別の制限まとめ

| 言語 | 実行 | 時間制限 | メモリ制限 | サードパーティライブラリ | ネットワーク |
|---|---|---|---|---|---|
| C | ブラウザ | なし | なし | 不可 | 不可 |
| JavaScript | ブラウザ | 10秒（固定） | なし | 不可 | Worker内で技術的には可能だが依存しないこと |
| TypeScript | ブラウザ | 10秒（固定） | なし | 不可 | 同上 |
| Python | ブラウザ | 15秒（固定） | なし | 不可（標準ライブラリのみ） | 不可 |
| Java | サーバー | テストケース設定（既定2秒） | テストケース設定（既定256MB） | 不可 | 不可 |

> テストケースごとの時間・メモリ制限は現在 **Javaでのみ**有効です（値はAPI経由でのみ変更可能で、問題編集UIには項目がありません。既定値のままで運用してください）。C / JS / TS / Pythonは上表の固定値です。
