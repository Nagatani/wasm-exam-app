# 対応言語ガイド

問題は **1問につき1言語**で、講師が問題編集画面で選びます。生徒側に言語の切り替えはありません。

このドキュメントは「その言語で解答を書くとき／その言語の問題を作るときに知っておくべきこと」をまとめたものです。問題文（Markdown）に入出力形式を明記するときの参考にしてください。

## 言語の一覧

| 言語 | 「実行」（お試し）の場所 | 実行環境 | 時間制限 | メモリ制限 |
|---|---|---|---|---|
| C | ブラウザ | clang（WebAssembly） | 10秒 | 256MB（超過は確保失敗 → RE） |
| JavaScript | ブラウザ | Web Worker | 10秒 | なし |
| TypeScript | ブラウザ | Web Worker（`sucrase` で型を除去） | 10秒 | なし |
| Python | ブラウザ | Pyodide（CPython の WebAssembly 版） | 15秒 | Pyodide の上限（`MemoryError` → MLE） |
| Java | サーバー（judge） | JDK 24（`--enable-preview`） | テストケースごと（既定2秒） | テストケースごと（既定256MB） |

- どの言語でも、サードパーティのライブラリとネットワークは使えません。
- **本採点**（最終提出・時間切れ自動提出・再採点）は、全言語ともサーバー（judge）が保存済みの下書きを実行して行います。judge はブラウザと同じ実行環境・同じ時間制限を使うので、「実行」で AC だったプログラムが本採点で別の結果になることは原則ありません（例外は実行時間が制限ぎりぎりのプログラムで、端末と judge の速さの違いで TLE になるかどうかが変わることがあります）。
- テストケースごとの時間制限（100〜15000ms）・メモリ制限（16〜512MB）を設定できるのは **Java** だけです。C / JS / TS / Python は上表の固定値です。
- 送信できるソースコードは全言語共通で **200,000バイト**（UTF-8）までです。

## 採点のルール

- **判定はサーバーが行います**。
  - 本採点は judge が下書きを実行して判定します。ブラウザの実行結果は使いません。
  - 「実行」では、C / JS / TS / Python は生徒のブラウザが「各テストケースの標準出力」と「コンパイル成否」だけを報告し、合否はサーバーが判定します（合否そのものは申告できません）。Java は「実行」もサーバーで行います。
  - judge を使わない構成（運用で judge を停止・未設定にした場合）では、本採点もブラウザの実行結果をもとにサーバーが判定します。
- **出力の比較方法は問題ごとに講師が選べます**（既定は「完全一致」）。
  - **完全一致（EXACT）**：両方の前後の空白を除いて文字列比較。`42` と `42\n` は一致、`1 2` と `1  2` は不一致、途中の改行は区別。
  - **行末の空白と末尾の空行を無視（TRIM_TRAILING_WS）**。
  - **空行をすべて無視（IGNORE_BLANK_LINES）**（行末の空白も無視）。
  - **数値を許容誤差付きで比較（FLOAT）**：空白で区切ったトークン列を比較し、数値は講師が設定した許容誤差以内なら一致（数値以外は完全一致）。
  - **大文字・小文字を無視（IGNORE_CASE）**：行末の空白・末尾の空行を無視した上で、大文字小文字の違いも無視。
- **非公開テストで WA になったとき、答えを明かさない範囲でヒントが出ることがあります**（例：「空白や改行の違いの可能性があります」）。緩い比較方法でも一致しない場合はヒントなしです。期待される出力の内容・行数は含まれません。
- 1テストケースの結果：
  - **AC** … 出力が期待値と一致
  - **WA** … 出力が期待値と不一致
  - **RE** … 実行時エラー（例外・異常終了）
  - **TLE** … 実行時間の上限を超過
  - **MLE** … メモリの上限を超過（Java と Python で検出。C は 256MB を超える確保が失敗して RE などになります。JavaScript / TypeScript はブラウザの仕組み上、メモリを制限・検出できません）
- 問題全体の判定：
  - **AC** … 全テストケースが AC
  - **TLE** / **MLE** … AC でないテストケースがすべて TLE（またはすべて MLE）のとき
  - **WA** … それ以外で AC でないテストケースがある（RE もここに含まれる）
  - **CE** … コンパイル／構文エラー
- **得点**：既定では、問題全体が AC のときだけ配点が入り、それ以外は0点です。講師が「部分点を認める」を有効にした問題では、通過したテストケース数（サンプル・非公開とも）÷ 総数 の割合を配点に掛けて四捨五入します（判定の表示は変わりません）。CE はどちらでも0点です。
- サンプルでないテストケースの「期待される出力」は生徒のブラウザに一切送られません。生徒に見えるのは入力だけです。
- **試験モード**では、「実行」は結果を表示するだけ（保存なし）、「下書き保存」は解答を保存するだけ（採点なし）です。採点は試験全体の「最終提出」で、保存済みの各下書きをまとめて行います。最終提出後の修正・再提出はできません（受験可能回数が残っていれば、白紙の新しい回として受け直せます）。制限時間が切れると、その時点の下書きが自動的に最終提出されます。
- **演習モード**では下書きはなく、「実行（お試し）」は結果を表示するだけ、「提出する」は毎回全テストケースで判定して提出履歴に記録します。判定ルールは試験モードと同じです。

## C

| 項目 | 内容 |
|---|---|
| 実行場所 | 生徒のブラウザ（clang を WebAssembly で動かしてコンパイルし、WASI で実行） |
| コンパイル単位 | `main.c` |
| 標準入出力 | 通常どおり `stdin` / `stdout`（`scanf`, `printf` など） |
| 使えるもの | C 標準ライブラリ。ファイル I/O・ネットワークなどの環境依存の機能は使えません |
| 型の大きさ | WebAssembly（wasm32）のため `long` とポインタは **4バイト**（`long long` は8バイト）。ブラウザと judge で共通です |
| 実行時間の上限 | **10秒**（超えると打ち切って TLE）。無限ループでも10秒で完全に止まり、次の実行に影響しません |
| メモリの上限 | **256MB**。超える `malloc` は `NULL` を返します（そのまま使うと実行時エラー）。MLE ではなく RE / WA になります |
| 初回の読み込み | clang ツールチェイン 約106MB を初回のみダウンロード。低速回線では最初のコンパイルに数分かかることがあります（以降はブラウザのキャッシュ） |

## JavaScript

| 項目 | 内容 |
|---|---|
| 実行場所 | 生徒のブラウザ（テストケースごとに新しい Web Worker） |
| 実行時間の上限 | **10秒**（超えると強制終了して TLE） |
| コンパイルエラー | 構文エラーのみ（実行前に検出。位置がエディタに表示されます） |

`process` や `require` はありません。代わりに次のグローバルが使えます。

| 名前 | 用途 |
|---|---|
| `readline()` | 標準入力を1行返す（改行は含まない）。行がなくなったら `''` |
| `readLine()` | `readline()` の別名 |
| `read()` | 残りの標準入力をまとめて文字列で返す |
| `print(...args)` | 引数をスペース区切りで出力し、末尾に改行。オブジェクトは JSON で出力 |
| `console.log` / `.error` / `.warn` / `.info` / `.debug` | すべて標準出力へ（`print` と同じ） |
| `write(s)` | 改行なしで出力 |

- トップレベルの `return` は使えます（コードは関数本体として実行されます）。
- **トップレベルの `await` は使えません**。
- テストケースごとに新しい Worker で実行するため、グローバル変数はテストケース間で引き継がれません。

**例（`n` を2倍にして出力）**

```js
const n = Number(readline());
console.log(n * 2);
```

## TypeScript

JavaScript と同じ仕組みで動きます。実行前に **`sucrase` で型注釈を取り除くだけ**で、型チェックはしません。

- **型エラーは採点に影響しません**。
- **構文エラーはコンパイルエラー（CE）** になります。
- 入出力のヘルパー・制限・注意点は JavaScript と同じです。
- 型定義（`lib.d.ts`）は読み込まれないため、`document` や Node の型など「型としてはあるが実行時にはない」ものに依存しないでください。

**例**

```ts
const n: number = Number(readline());
const doubled: number = n * 2;
console.log(doubled);
```

## Python

| 項目 | 内容 |
|---|---|
| 実行場所 | 生徒のブラウザ（Pyodide = CPython の WebAssembly 版、Web Worker 内） |
| 実行時間の上限 | **15秒**（超えると強制終了して TLE） |
| メモリの上限 | Pyodide の上限まで。使い切って `MemoryError` になると **MLE** |
| 初回の読み込み | Pyodide 約10MB を初回のみ取得 |
| コンパイルエラー | 構文エラーのみ（実行前に `compile()` で検出） |

- 標準入出力は通常どおり `input()` / `print()` / `sys.stdin` / `sys.stdout`。
- 使えるのは **Python 標準ライブラリのみ**です。`pip` / `micropip` は無効で、`numpy` などは読み込めません。ネットワークも使えません。
- `sys.exit()` / `exit()` での終了は正常終了として扱います。
- 例外が送出されると、トレースバックが標準エラーに出て RE になります。
- ユーザーのコードはテストケースごとに新しいグローバル名前空間で実行されます（import 済みのモジュールは引き継がれます）。

**例**

```python
n = int(input())
print(n * 2)
```

## Java

| 項目 | 内容 |
|---|---|
| 実行場所 | **サーバー**（judge コンテナ内。ホストでは実行しません） |
| JDK | **24**、`--enable-preview` 付き（クラス宣言を省略できるコンパクトソース〈JEP 495〉が使えます） |
| コンパイル単位 | `Main.java`、エントリクラスは **`Main`** |
| 標準入出力 | 通常どおり `System.in` / `System.out`（`Scanner` など） |
| 実行時間の上限 | **テストケースごとの設定**（既定2秒、上限15秒）。超えると強制終了して TLE |
| メモリの上限 | テストケースごとの設定（既定256MB、上限512MB）。超えると MLE |
| 使えるもの | JDK 標準ライブラリ。標準出力・標準エラーは64KBを超えた分を切り捨て |

- クラスを宣言する場合、公開クラス名は **`Main`** にしてください（`public class Solution` などはファイル名と合わずコンパイルエラーになります）。
- コンパクトソース（クラス宣言なしのインスタンス `main`）も使えます。
- judge が停止している、または `JUDGE_URL` が空の場合、Java の問題は生徒側で「準備中」と表示され、実行・提出できません（[operations.md](./operations.md)）。

**例（クラスあり）**

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        System.out.println(n * 2);
    }
}
```

**例（コンパクトソース）**

```java
void main() {
    var sc = new java.util.Scanner(System.in);
    System.out.println(sc.nextInt() * 2);
}
```
